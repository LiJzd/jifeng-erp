# 集沣 ERPNext 二开（第一阶段）

本目录是独立的 Frappe 应用，配合旁边的 ERPNext `version-16` 使用。当前实现聚焦录音里最费时的销售/成品回货计价：同一流程单分批回货、部分返工、损耗和追加加工费的**试算**。试算单不创建 Stock Entry、Subcontracting Receipt、Sales Invoice 或 GL Entry，也不改库存估值。

## 使用范围

- `Jifeng Cost Preview`：记录公司、流程单号、外部采购/订单号、ERPNext 销售订单、委外订单、商品编码、计划数量和费用。
- `Jifeng Cost Batch`：按时间顺序记录首次回货和返工回货，分别填合格、待返工、损耗、待检数量以及追加加工费。保存时验证数量并更新结果。
- 首次回货只消耗未回货数量；返工回货只消耗此前的待返工数量，不会再次计入材料数量。
- 单位成本试算口径：`(材料费 + 基础加工费 + 其他费用 + 各批追加加工费) / (计划数量 - 已确认损耗)`。未回货、待检、待返工数量仍属于“可能合格”的分母；每批合格品按数量试算金额。未结清时，后续成本或损耗会改变此前批次的试算金额。
- 按累计合格数量分位舍入，避免多批次逐行舍入超分摊。若全部损耗，费用保留在“尚未分摊金额”，不产生虚假的单位成本。

例如：计划 100 件，材料费 100 元、基础加工费 50 元；第一批 50 件合格，第二批 50 件返工；返工回 48 件合格、2 件损耗，并新增加工费 20 元。试算总费用 170 元，最终合格 98 件，材料只计算一次。

## 本地安装

需要可运行的 Linux/WSL Frappe Bench、MariaDB/Redis、Python 3.14 与对应 ERPNext v16。当前 Windows 目录只有源码；本机 Docker Engine 尚未运行，尚未执行站点安装验证。

在已初始化且安装 Frappe/ERPNext v16 的 bench 中：

```bash
bench get-app /path/to/jifeng_erp
bench --site YOUR_SITE install-app jifeng_erp
bench --site YOUR_SITE migrate
```

在 Desk 搜索“Jifeng Cost Preview”新建试算单。每行“回货数量”应等于合格、返工、损耗、待检数量之和；返工回货行放在产生待返工数量的行之后。

## 录音需求与后续联调条件

ERPNext 原生 `Item` 支持商品编码、图片、规格/描述、供应商资料；BOM、Operation、Routing 与 Subcontracting Order/Receipt 可承接物料及委外工序。录音中这些字段的实际来源、现有历史数据和价格口径尚未提供，因此本阶段没有改原生凭证或臆造聚水潭接口。

聚水潭订单、图片、定制/包装要求的自动同步需要 API 权限或订单导出样例及字段说明；钉钉群文件的归档方式也需实际样例。真实库存估值/财务入账还需确认损耗承担方、返工费归属、后补费用处理、跨批次四舍五入和现有仓库/科目设置。拿到样例后应先在测试站点用“100 件→50 合格+50 返工→48 合格+2 损耗”的实际单据走通委外收货，再决定是否把试算接入记账。
