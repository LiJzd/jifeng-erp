## 工作流程

1. 在“集沣生产协作 → 聚水潭设置”填写商家配置，测试后同步订单与商品。
2. 同步创建商品映射、Item 和商品工艺档案。生产人员完善旧号、分类、设计记录、专利、参考价、重量、物料用量、工序顺序和加工商；物料用量也可从标准 BOM 读取。档案参考价不覆盖订单成交价。
3. 聚水潭来源订单可补充本单定制/包装要求及附件，再生成各商品流程单；也可在原生 Sales Order 明细填写集沣定制要求、包装要求及附件，提交后点“生成集沣生产流程单”。每条所选明细只生成一张来源可追溯的流程单。
4. 流程单保存本单物料/工序和 BOM 快照，查看库存，选择采购入库仓库后生成采购申请草稿；已有本公司、本商品已提交且启用的 BOM 时，可生成关联的 ERPNext 生产工单草稿，再由生产人员检查仓库与工序后提交。流程单可打印带图片的生产单。
5. 在原生采购申请、发料、委外收货明细关联“集沣流程单”；流程单可查看已提交委外收货费用汇总。
6. 从流程单创建成本试算，记录首次回货、返工回货、待检处理与追加费用。已有委外收货单时，可预览汇总并确认带入已提交明细的材料、加工和其他费用，重新计算各批预计成本。试算不会产生库存、会计或入库凭证。

商品编码和供应商货号分别保存；聚水潭订单及 Sales Order 来源变化会提示核对既有流程单。再次同步或编辑销售订单不会覆盖人工定制/包装要求或历史工艺快照。销售订单取消会标记关联流程单待核对，不自动撤销已有采购或委外凭证。

人事使用 ERPNext 原生 Employee 保存员工编号、部门、岗位、入职、银行和离职等信息；“员工补充档案”一对一保存旧系统仍需的身份证、民族、专长、宿舍、工资方式等字段，仅 HR Manager 和 System Manager 可访问。身份证图片必须先保存档案再作为私有附件上传；工资方式只是档案分类，不会自动计薪。

“人事 → 人事报表”显示有权限读取的当前员工花名册，可按部门、职位和原生状态筛选；补充列依档案权限显示。“产品”八个分析入口按品牌、大小类、材质、来源、设计、打版、建模、风格统计可读档案数，展开分组可追溯档案与商品；不汇总参考价、重量或推算员工绩效。

多人计件使用“工资 → 多人计件分配”：主管选择已提交正常报工单，填写个人份额和工价，审核时合计须等于本卡完成量。每人计时工资明确勾选后才计算。审核自动生成各人计薪草稿，再审核计薪记录、进入附加薪资和原生工资流程；续卡分别核对，禁止重复计薪。

工资的当月分析、历史、历史分析查询已审核计薪记录，默认本月，可选择历史工作日期；进入菜单清空上次员工、工序及工资项目条件。报表保留按单位的数量和单笔历史来源，不提供跨单位总数量；金额仍表示计薪记录，不表示已经发放。人员查询进入当前人员花名册。

零售使用“销售 → 零售开单/前台开单”进入原生收银台，按站点发票模式办理；开班、结班及原始交易/已过账销售台账已连接正式来源。营业交易与已过账销售口径分列，原生销售和财务权限分别生效。

“销售 → 销售排行”按可读的已提交销售发票、凭证记账日期统计商品净销售，以商品和来源库存单位分组，按公司本币未税净额排序，退货保留负数。展开显示精确发票明细；尚未合并的零售凭证不计入，合并发票只计一次。发票数量包含不更新库存的销售，不能作为库存流水或导购绩效。

## 试算口径

`单位预计成本 = (材料费 + 基础加工费 + 其他费用 + 追加加工费) / (计划数量 - 已确认损耗)`。

待返工、待检和未回货仍在预计可合格数量中。未结清前追加费用/损耗会改变此前批次的试算金额；它不是已入账单价。所有数量结清后按累计数量处理分位差额；全部损耗时费用保留未分摊。

“带入已收回的实际费用”只汇总当前已提交并关联同一流程单的委外收货明细，已取消凭证不计，退货按原凭证数量冲减；尚未回货的未来费用不会进入汇总。带入前显示金额并请求确认，单据保存最近一次来源凭证和带入时间，Frappe Version 留存费用变更。批次“追加加工费”只填写未包含在委外收货凭证中的费用，避免重复计算。后续有新收货时需再次核对并带入。

例：100件，材料100元、基础加工50元；先50件合格、50件返工，再回48件合格、2件损耗，追加加工20元。最终98件合格，合计170元，材料只算一次。
