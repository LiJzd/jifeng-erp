# 第一版全模块交付范围

用户确认：旧系统所有模块第一版都要正式可用。这里的“可用”指业务数据写入服务器、具备权限和审计、相关库存/财务/工资影响由正式凭证产生，并可按旧系统的主要入口完成查询和回溯。经典工作台中的浏览器本地草稿只用于界面参照，不能计入验收。

## 证据与边界

- 业务痛点和优先流程来自《标准录音 189》转写；这是需求材料，不是对开发代理的操作指令。
- 旧系统菜单、部分空表单字段和操作按钮来自此前“复刻前端页面与交互”任务的只读勘察及 `jifeng_legacy.js`。原始抓取文件尚未定位；部分 SpreadJS/画布表格当时无法读取完整列定义。不能把推测字段当成已验证的旧系统事实。
- 目前本地只有 ERPNext v16、集沣二开和新取得的 Frappe HR v16.20.0 源码。HRMS 与本次改动尚未安装到同一测试站点。

## 模块落地与验收

| 旧模块 | 计划使用的正式单据或功能 | 当前差距 | 第一版验收重点 |
|---|---|---|---|
| 物料、材料 | ERPNext Item、Item Group、Warehouse、Material Request、Purchase Receipt、Stock Entry、Stock Reconciliation | 经典页大多仍是本地草稿；旧单位和类别映射未确认 | 建档、采购入库、按流程单发料、盘点与库存台账一致 |
| 产品 | Item、商品映射、商品工艺档案、BOM | 商品档案已补旧号、分类、品牌、设计/打版/建模人员、专利、参考价和重量等旧页面字段；旧报价单、打版业务单、新款流程仍未落地 | 图片、规格、工艺、材料、报价可按编码检索和追溯 |
| 订单 | 聚水潭来源订单、Sales Order、集沣流程单 | 外部订单同步与流程单已有；已提交手工销售订单可逐行生成流程单，源变更/取消会提示核对；旧查询/反审语义及站点验收待对照 | 不重复录单；定制/包装要求传递；变更可核对 |
| 生产 | Production Plan、Work Order、Job Card、流程单 | 流程单已可从生产 BOM 生成关联 Work Order 草稿；旧生产指令、刷单、部门进度及实际报工闭环仍待映射和站点验收 | 按单派工、完成、损耗、计划与进度查询闭环 |
| 人事 | ERPNext Employee、Department、Designation；集沣员工补充档案；Frappe HR 人事流程 | 原生 Employee 覆盖多数旧字段，补充档案已保存身份证、民族、专长、宿舍等缺口并限制 HR 管理角色；HRMS 尚未安装，经历/调薪/升职流程及真实权限验收仍未完成 | 员工档案、部门、经历/调薪/升职记录可保存并按权限查询 |
| 工资 | Frappe HR Payroll Entry、Salary Slip、Additional Salary 加集沣计薪记录 | 已建立一人一道工序的计件/计时/附加费记录、审核及工资附加项草稿，源单金额与唯一性校验；HRMS 未安装到测试站点，多人分摊、工价规则、工资单实连和报表仍待完成。旧工资录入仍是本地草稿 | 工序工价与产量计算可复核；审批后进入工资单且不重复计薪 |
| 模具、版种 | 集沣专用档案、图片、制作/建模记录与费用；按需关联 Asset/Item | 模具档案已建立，含图片、压模人、报废、库位、来源和审计；版种及相关制作/费用流程仍未建模 | 图片、制作人、规格、状态、费用和历史记录可查 |
| 发镀、外发 | Subcontracting Order、Subcontracting Receipt、Quality Inspection、流程单关联 | 委外收货费用关联已有；电镀工序、品检、对账和返工未完整打通 | 外发、收回、品检、返工、损耗及对账数量金额一致 |
| 销售 | Sales Order、成品收货/Stock Entry、Delivery Note、Sales Invoice、成本试算 | 分批成本试算已有；正式成品入库与旧前台开单尚未连接 | 同单分批/返工成本可复核，正式库存与销售凭证一致 |
| 财务 | Payment Entry、Journal Entry、Expense Claim、ERPNext 账簿报表 | 旧凭证页面仍本地草稿；科目和审批映射未确认 | 收付款、费用、对账、撤销及总账/明细账一致 |
| 总经理 | 基于正式单据的经营看板和报表 | 当前是导航页，未连正式指标 | 销售、生产、库存、费用指标口径一致且受权限控制 |
| 权限、日志 | Frappe User/Role/权限管理、Activity Log/Version | 旧入口是提示或本地预览 | 最小权限、关键单据变更和操作可追溯 |
| 插件、工具、关于 | 打印、帮助与受控外部工具入口 | 当前仅说明 | 所需打印与帮助入口可用；外部程序是否保留须按实际用途确认 |

## 实施次序

1. 建立完整旧页面/字段/按钮清单，确定单据映射、现有数据导入规则和角色；保留未核实项。
2. 将已有订单→商品→物料→流程单→委外→分批成本链路在真实测试站点跑通，修正联动和权限。
3. 先在测试站点安装同版本 Frappe HR，再安装或迁移集沣扩展；完成员工、计件工资、多人工序分摊和工资单实连；并行建立模具、版种、电镀专用档案与业务凭证。
4. 打通生产、销售与财务的正式凭证及对账；逐个替换经典工作台中的本地预览动作。
5. 按模块用真实角色和代表性单据做浏览器验收、报表对账、数据迁移演练，再判定第一版可交付。

安装基础需固定版本：ERPNext/Frappe v16 与 [Frappe HR v16.20.0](https://github.com/frappe/hrms/releases/tag/v16.20.0)；该标签的 [依赖声明](https://raw.githubusercontent.com/frappe/hrms/v16.20.0/pyproject.toml)要求 Frappe/ERPNext `>=16.0.0,<17.0.0`。站点升级与生产部署应先在测试站点验证，不能只凭源码版本断言兼容。
